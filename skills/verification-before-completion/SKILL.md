# การตรวจสอบก่อนบอกว่าเสร็จ

## ภาพรวม

**หลักการ:** หลักฐานมาก่อนคำกล่าวอ้างเสมอ

**ละเมิดตัวอักษรของกฎนี้ คือละเมิดเจตนารมณ์ของกฎนี้**

## กฎเหล็ก

```
ห้ามอ้างว่างานเสร็จ ถ้าไม่มีหลักฐานการตรวจสอบที่สดใหม่
```

ถ้ายังไม่ได้รันคำสั่งตรวจสอบในข้อความนี้ ก็ห้ามอ้างว่ามันผ่าน

## ขั้นตอนบังคับ

```
ก่อนจะอ้างสถานะใดๆ หรือแสดงความพอใจ:

1. ระบุ: คำสั่งไหนพิสูจน์คำอ้างนี้ได้?
2. รัน: สั่งคำสั่งแบบเต็ม (สดใหม่ ครบถ้วน)
3. อ่าน: ผลลัพธ์ทั้งหมด ดู exit code นับจำนวนที่ล้มเหลว
4. ตรวจ: ผลลัพธ์ยืนยันคำอ้างหรือไม่?
   - ถ้าไม่: บอกสถานะจริงพร้อมหลักฐาน
   - ถ้าใช่: บอกคำอ้างพร้อมหลักฐาน
5. จากนั้นเท่านั้น: จึงอ้างได้

ข้ามขั้นใด = โกหก ไม่ใช่การตรวจสอบ
```

## ความล้มเหลวที่พบบ่อย

| คำอ้าง | ต้องมี | ไม่เพียงพอ |
|-------|--------|-----------|
| เทสต์ผ่าน | ผลจากคำสั่งเทสต์: ล้มเหลว 0 | รันครั้งก่อน, "น่าจะผ่าน" |
| Linter สะอาด | ผลจาก linter: error 0 | ตรวจแค่บางส่วน, การคาดเดา |
| Build สำเร็จ | คำสั่ง build: exit 0 | linter ผ่าน, log ดูโอเค |
| บั๊กถูกแก้ | ทดสอบอาการเดิม: ผ่าน | แก้โค้ดแล้วเดาว่าหาย |
| Regression test ใช้ได้ | ยืนยันวงจร red-green แล้ว | เทสต์ผ่านครั้งเดียว |
| Agent ทำเสร็จ | VCS diff แสดงการเปลี่ยนแปลง | Agent รายงานว่า "สำเร็จ" |
| ตรงตามข้อกำหนด | checklist ทีละบรรทัด | เทสต์ผ่าน |

## สัญญาณเตือน - หยุด

- ใช้คำว่า "น่าจะ", "คงจะ", "ดูเหมือนว่า"
- แสดงความพอใจก่อนตรวจสอบ ("เยี่ยม!", "สมบูรณ์!", "เสร็จแล้ว!" ฯลฯ)
- กำลังจะ commit/push/สร้าง PR โดยไม่ได้ตรวจสอบ
- เชื่อรายงานความสำเร็จของ agent
- พึ่งการตรวจสอบแค่บางส่วน
- คิดว่า "ครั้งนี้ครั้งเดียว"
- เหนื่อยและอยากให้จบ
- **ถ้อยคำใดๆ ที่สื่อว่าสำเร็จ ทั้งที่ยังไม่ได้รันการตรวจสอบ**

## ป้องกันการหาเหตุผลเข้าข้างตัวเอง

| ข้ออ้าง | ความจริง |
|--------|---------|
| "ตอนนี้น่าจะใช้ได้แล้ว" | รันการตรวจสอบสิ |
| "มั่นใจ" | ความมั่นใจ ≠ หลักฐาน |
| "ครั้งเดียวเอง" | ไม่มีข้อยกเว้น |
| "Linter ผ่านแล้ว" | Linter ≠ คอมไพเลอร์ |
| "Agent บอกว่าสำเร็จ" | ตรวจสอบเองอย่างอิสระ |
| "เหนื่อยแล้ว" | ความเหนื่อยไม่ใช่ข้ออ้าง |
| "ตรวจแค่บางส่วนก็พอ" | บางส่วนพิสูจน์อะไรไม่ได้ |
| "ใช้คำต่างกัน กฎเลยไม่ครอบคลุม" | เจตนารมณ์สำคัญกว่าตัวอักษร |

## รูปแบบที่ใช้

**เทสต์:**
```
✅ [รันคำสั่งเทสต์] [เห็น: 34/34 ผ่าน] "เทสต์ผ่านทั้งหมด"
❌ "น่าจะผ่านแล้ว" / "ดูถูกต้อง"
```

**Regression test (TDD Red-Green):**
```
✅ เขียน → รัน (ผ่าน) → ย้อนการแก้ → รัน (ต้องล้มเหลว) → คืนการแก้ → รัน (ผ่าน)
❌ "เขียน regression test แล้ว" (โดยไม่ได้ยืนยัน red-green)
```

**Build:**
```
✅ [รัน build] [เห็น: exit 0] "Build ผ่าน"
❌ "Linter ผ่าน" (linter ไม่ได้ตรวจการคอมไพล์)
```

**ข้อกำหนด:**
```
✅ อ่านแผนซ้ำ → สร้าง checklist → ตรวจทีละข้อ → รายงานช่องว่างหรือความสมบูรณ์
❌ "เทสต์ผ่าน เฟสนี้เสร็จ"
```

**การมอบหมายให้ agent:**
```
✅ Agent รายงานสำเร็จ → ตรวจ VCS diff → ยืนยันการเปลี่ยนแปลง → รายงานสถานะจริง
❌ เชื่อรายงานของ agent
```

## เมื่อไหร่ต้องใช้

**ต้องใช้ก่อนทุกครั้งที่:**
- พูดอะไรก็ตามที่สื่อว่าสำเร็จหรือเสร็จ
- แสดงความพอใจในรูปแบบใดๆ
- พูดเชิงบวกเกี่ยวกับสถานะของงาน
- Commit, สร้าง PR, ปิดงาน
- ไปทำงานถัดไป
- มอบหมายให้ agent

**กฎนี้ครอบคลุม:**
- ถ้อยคำตรงตัว
- การถอดความและคำพ้อง
- นัยที่สื่อถึงความสำเร็จ
- การสื่อสารใดๆ ที่บอกว่าเสร็จหรือถูกต้อง
